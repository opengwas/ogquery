# ogquery Domain Glossary

ogquery is opengwasdb's Store Reader as its own package, so it shares opengwasdb's
vocabulary. **Shared terms are defined in
[opengwasdb's CONTEXT.md](https://github.com/opengwas/opengwasdb/blob/main/CONTEXT.md)**,
and are not repeated here: Store Release, Format Version, Primary Storage Layout (Dense,
Ragged, Hybrid), Dense Component, Analysis, Variant Index, Variant Axis, ALID Search
Index, Store Variant Table, Top-Hit Index, Indexed Variant Subset, Association Status,
Observed-Only Query, Store Reader and Store Reader Contract Bundle among them, and the LD
terms: LD Store, Variant Set, Near Band, Far Pairs, Partner Rows, Far Threshold (t_far),
Refusal, Genotype Store, Test Panel and Test Store. Use them as
defined there (Analysis, not phenotype; Store Release, not dataset). A change to a shared
term is made there.

This file defines only what is ogquery's own.

## Language

**ogquery**:
The distribution of the **Store Reader** (opengwasdb's term): the package `ogquery`. Its
runtime dependencies, its core, are numpy, zarr and numcodecs, and nothing else (a **Clean
Install**). The core reads every GWAS Store and every LD Store from a local path without any
extra. Two optional extras each add one kind of read: the **HTTP Extra** reading a Store over
HTTP(S), and the **Genotype Extra** a Genotype Store, which needs it. Its modules are the ones
`opengwasdb.store_reader` had, by the same names (ADR 0001).
_Avoid_: query engine, client (opengwaspy and opengwasr are the clients).

**Variant Table Reader**:
What a caller passes as `open_release(path, legacy=...)` so ogquery can query a 0.2.x or
0.1.0 Store Release: an implementation of `ogquery.variant_axis.LegacyVariantTable`,
which reads that release's BGZF/tabix Store Variant Table and its `variant_aliases`.
ogquery defines the protocol and implements none that needs pysam; opengwasdb implements
it. Without one, querying such a release raises `VariantTableReaderRequired`, naming its
format version and how it becomes 0.3.0: `ogdb rewrite-release` for a 0.2.3 release, a
rebuild from source for an earlier one. A 0.3.0 release needs none.
_Avoid_: legacy reader, legacy provider.

**Bundle Source**:
The opengwasdb commit the committed contract bundle came from, named in
`tests/contract/SOURCE`. The bundle's data (`releases/`, `expected/`, `VERSION`,
`.gitattributes`) is that commit's byte for byte; ogquery never edits it, and takes a
newer one by refreshing from a later commit.

**LD Test Data**:
`tests/ld/data/`: the Test Panel's answers and its Test Store, and the sorted spelling's
committed answers, copied from the opengwasdb commit `tests/ld/data/SOURCE` names, with each
file's git blob id there (ADR 0002); and what opengwasdb's own code generated once, recorded
there apart from the copies: two stores, the k = 0 Test Store and the Test Panel's Genotype Store
(with the genotypes it pins), and opengwasdb's answers on that Genotype Store. Like the contract
bundle it is opengwasdb's, generated by its code and read only here; `tests/ld/test_source.py`
holds every file to its blob id.
_Avoid_: fixtures (they are not this repository's to change).

**HTTP Extra**:
An optional extra, not a core dependency. `ogquery[http]`: fsspec and aiohttp, which zarr opens an `http(s)://` Store with. Not part of a
Clean Install; without it such an open raises `ogquery.opening.HttpExtraMissing`, naming it.

**Genotype Extra**:
An optional extra, not a core dependency. `ogquery[genotype]`: pgenlib and threadpoolctl, which a Genotype Store's reader
(`ogquery.ld.genotypes`) computes r with and holds BLAS to one thread with, where threadpoolctl
controls the BLAS. Not part of a Clean
Install, and no Windows wheel of pgenlib exists; without it opening a Genotype Store raises
`ogquery.opening.GenotypeExtraMissing`, naming it. `ogquery/ld/genotypes/` is the one package that
imports either (ADR 0002, amended). A Genotype Store is read from a local path only.

**Byte Genome**:
A release assembly's primary contigs (GRCh38's 25) as one memory-mapped file of uint8, one
upper-cased ASCII byte per base in the variant order, beside a JSON sidecar holding each
contig's offset, length and SHA-256, the sequence digest (opengwasdb ADR 0108 §9), the file's
SHA-256 and its provenance (ADR 0003). `ogquery.genome` writes it from contig sequences an
engine hands it (`write_byte_genome`) and reads it with numpy alone (`ByteGenome`). It is the
reference CPRA formation reads, so builds, ogquery and the Data API spell a CPRA from one
byte-identical sequence. Its `digest()` is computed from the bytes; the sidecar's is only what
`verify()` compares against.
_Avoid_: reference FASTA (the FASTA is its recorded source, read by the engine), 2-bit genome.

**CPRA Status**:
What `ogquery.cpra.to_cpra` says of a variant it was asked to spell: `ok`, with its CPRA
(opengwasdb ADR 0108's key, `chrom:pos:REF:ALT`), or why it has none: `ref_mismatch` (a
declared reference the genome does not carry), `allele_not_reference` (neither allele is the
genome's; never complemented), `indel_unresolved` (an indel whose source declares no
reference) or `off_sequence` (an `N`, or a span leaving its contig). The same five as
opengwasdb #518's alignment tool, which adds `lift_failed` for its own lift. Malformed input
(an empty or non-ACGT allele, two alleles alike) is a caller's bug and raises instead.

**Clean Install**:
A fresh virtual environment into which `pip install ogquery` was run with source builds
refused: it must hold ogquery, numpy, zarr, numcodecs and their own dependencies, and
nothing else, every one from a wheel (`scripts/check_installed_dependencies.py`). CI
checks one on Linux, macOS and Windows.
