**Every entry point an integer index can reach now requires `expect_release_id=`, and refuses a mismatch (opengwas/ogquery#13, opengwasdb ADR 0109 §2).** A splice renumbers `analysis_index` and `variant_index`, so an index cached from another release is still in range and names a different Analysis or variant without failing. `VariantAxis` and `PanelVariantAxis`: `by_index`, `by_indices`, `identity_by_indices`, `rsids_by_indices`, `source_alids_by_indices`, `rows_by_indices`; `DenseRhoReader.row`, `pair`, `matrix`; `TopHitTier.clumps`; `IndexedSubset.decode_analysis` each take a keyword-only `expect_release_id` with no default, and raise `ogquery.guard.ReleaseMismatchError` (a `ValueError`) naming both ids. The reader objects know their release (`release_id`; `query.release_id` on a facade). An `Associations` answer carries the `release_id` it was read from, outside its mapping view, so no digest changes; `resolve` and `resolve_rows` refuse a result read from another release, or one with none. The constructors `VariantAxis`, `PanelVariantAxis`, `DenseRhoReader`, `TopHitTier` and `TopHitTiers` take a required `release_id`. Also: `digests.Reference` serialises (`to_json`, `from_json`).
